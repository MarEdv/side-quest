# Decisions & Assumptions Log (Side Quest Project)

> Append-only. Each entry: ID, date, decision, alternatives considered, rationale.
> If a decision is reversed, add a new entry that supersedes the old one (don't delete).
> Game-specific decisions live in `games/<slug>/docs/DECISIONS.md`.

## Decisions

### D-1 — One monorepo in MarEdv/side-quest; games under games/<slug>/ (2026-11-10)
- **Chosen:** Reuse the existing `MarEdv/side-quest` repo. Its history is kept as-is (no rewrite, no force push): one
  commit moves every file into `games/side-quest/`. `MarEdv/poo-sandwich` was rewritten with
  `git filter-repo --to-subdirectory-filter games/poo-sandwich` and merged with `--allow-unrelated-histories`. The
  launcher lives at the root. The unmerged `worktree-statusline-mod` branch was not migrated (it stays in the old clone).
- **Alternatives:** a new `side-quest-project` repo (new URL, both old repos to archive); rewriting both histories into
  subfolders (force push to side-quest); `git subtree add` (keeps commits but old paths, so `git log` on a file needs
  more care); games at the repo root instead of `games/`.
- **Rationale:** Owner chose to reuse the repo and the `games/<slug>/` layout. A move commit keeps existing SHAs and
  links valid, and `git log --follow` still traces files through it.
- **Consequence:** https://maredv.github.io/side-quest/ is now the launcher; Side Quest is at `…/side-quest/games/side-quest/`,
  Poo Sandwich at `…/side-quest/games/poo-sandwich/`.

### D-2 — Retire Side Quest's root service worker with a root sw.js (2026-11-10)
- **Context:** Installed copies of Side Quest have a worker registered at `/side-quest/sw.js` with scope `/side-quest/`, which
  now covers the launcher and every game. Deleting `sw.js` doesn't remove it (a 404 update keeps the old worker; see the
  game's D-26).
- **Chosen:** A root `sw.js` based on the game's `tools/sw-kill.js`. Browsers fetch it on their next visit; it deletes cache
  entries outside `games/` from `sidequest-*` caches and unregisters itself. Nothing registers it. The relocated game keeps
  its own worker (scope `games/side-quest/`) and its cache name, so its tests and code are unchanged.
- **Alternatives:** plain `sw-kill.js` (would also wipe the relocated game's precache, which uses the same cache name);
  renaming the game's cache (changes game code and its tests for no gain).
- **Keep it deployed** for as long as old installs may come back. localStorage (scores, settings) is per origin, so it survives.

### D-3 — Committed games.json, generated by a script (2026-11-10)
- **Chosen:** `tools/build-registry.mjs` writes `games.json` from `games/*/game.json`; the file is committed, and a test
  fails if it is stale.
- **Alternatives:** generate it in CI only (then `npm start` locally would need a build step); list folders at runtime
  (GitHub Pages has no directory listing); hand-edited list in the launcher (easy to forget, no validation).
- **Rationale:** Keeps the no-build-step rule and still makes "add a game" a folder + metadata change.

### D-4 — Launcher links to games; no iframe (2026-11-10)
- **Chosen:** Cards navigate to `games/<slug>/`.
- **Alternatives:** embedding games in an iframe with a shared shell.
- **Rationale:** Games are full-screen canvas games with touch input, safe-area handling and (Side Quest) an installable PWA;
  an iframe would interfere with all of that, and games stay runnable on their own.

### D-6 — The launcher is installable; manifest id shared with the old Side Quest app (2026-11-10) — retires L-5
- **Chosen:** Root `manifest.webmanifest` ("Side Quest Project" / short name "Side Quests", `display: standalone`,
  `scope: "./"` so every game opens inside the app window), icons generated by `tools/make-icons.mjs` (2x2 tile grid; PNG
  encoder copied from Garden Day), Apple meta tags, and an **Install app** button (`src/installmodel.js` pure rules,
  `src/launcher.js` glue): Chromium's `beforeinstallprompt`, iOS Share-sheet steps, hidden otherwise.
- **Manifest id `./`:** the same id and manifest URL as the old Side Quest app had at the site root. Browsers that installed
  Side Quest treat the launcher manifest as an update of that app (Chrome may confirm the new name and icon), so old installs
  turn into the launcher instead of becoming a dead app. Garden Day keeps its own, nested-scope app.
- **No service worker for the launcher:** current Chromium installs without one (Chrome 157: no installability errors), and a
  root worker would control Poo Sandwich too and clash with the retire worker at `sw.js` (D-2). So the launcher doesn't open
  offline. Alternative considered: turning the root `sw.js` into a launcher worker that also does the D-2 clean-up; left for
  later if offline launching is wanted.
- **L-5 retired:** "running standalone" now normally means "the launcher app", so the moved notice would show to every app
  user. The Garden Day card's description says "Formerly called Side Quest" instead.

### D-5 — Side Quest renamed to Garden Day; folder games/garden-day/ (2026-11-10)
- **Chosen:** Owner renamed the game. The folder (and URL) moved to `games/garden-day/`; the player-facing name changed in the
  title, menu heading, web app manifest, install texts, launcher card and docs. Kept: the gameplay term "side quests",
  localStorage keys (`sidequest.v1.*`) and cache names (`sidequest-*`), so scores, levels and settings survive.
- **Old URL:** `games/side-quest/` became a redirect stub (`game.json` `{ "movedTo": "garden-day" }`, skipped by the
  registry; `index.html` redirects with the query kept) plus a retire `sw.js` that drops cache entries under that folder and
  unregisters itself, for anyone who installed the game there.
- **Root `sw.js` amended:** it no longer deletes a cache it emptied, because the game's worker shares the cache name and could
  be filling it at the same moment.
- **Alternatives:** rename the display name only (stable URL, but a folder name that no longer matches the game); also rename
  storage keys (would wipe players' progress).
- **Trade-off:** an install from the old `games/side-quest/` address keeps opening the redirect; players who want a
  home-screen icon reinstall from `games/garden-day/`. The game was only at that path for a few hours.

### D-7 — Launcher in English and Swedish; the language is handed to the games as ?lang= (2026-11-15)
- **Chosen:** Owner asked for English and Swedish in the launcher and in each game, done separately per component.
  `src/i18n.js` (pure) holds the launcher strings and the language rules; `src/launcher.js` applies them through
  `data-i18n` / `data-i18n-html` / `data-i18n-aria` attributes and an **EN | SV** switch in the header, saved under
  `launcher.lang`. First visit: `?lang=` → saved choice → first supported `navigator.languages` entry → English.
- **Game texts:** `game.json` may carry `"i18n": { "sv": { "title"?, "description"? } }`; the registry validates it and
  copies it into `games.json`. Tags are translated in the launcher's dictionary (unknown tags show as written).
- **Hand-off to games:** card links are `games/<slug>/?lang=<lang>`, so a game opens in the language picked here. No shared
  storage key and no shared module: games keep their own translations and their own saved choice (rule 4), and a game
  opened directly or as its own installed app still follows that game's own setting or the browser language.
- **Names stay as they are:** "Side Quest Project", "Side Quests" and the game titles are proper names and are not
  translated (A-3).
- **Alternatives:** one shared i18n module for all games (breaks "games stay self-contained"); a shared `localStorage` key
  read by every game (hidden coupling between folders, and the launcher's choice would silently override a game's own
  setting even when the game is opened directly); translating the web app manifest (manifests have no per-language
  variant without separate manifest files, and the name is a proper noun anyway).

### D-9 — Shared code: a root kit/ folder, copied into each game by a script and checked by a test (2026-11-15)
- **Chosen:** The proposal in D-8, carried out as S-1 of `docs/STREAMLINING.md`. Canonical modules live in `kit/`. The
  launcher imports them directly. A game lists the modules it uses in its `package.json` (`"kit": [...]`), and
  `npm run kit` (`tools/sync-kit.mjs`) writes each one to `games/<slug>/src/kit/<name>.js` under a "generated, do not edit"
  header and removes copies that are no longer listed. The copies are committed. `tests/kit.test.js` fails when a copy is
  missing, edited or left over.
- **Why:** the same code had been copied by hand between the parts and the copies had drifted in behaviour (storage after a
  failed write, audio resume, zero seeds: `docs/STREAMLINING.md` section 3). Rule 4 forbids a game importing from outside
  its folder, so the copy has to stay; this makes it generated and verified, as `games.json` already is (D-3).
- **Details:** the list is per game, so a game only carries what it uses. A kit module may import another (`./x.js`); the
  script refuses a list that names one without the other. Module tests are root tests named `kit-<name>.test.js`, so the
  root test script is unchanged. The kit starts empty: each module arrives with the task that moves the code (S-3..S-13).
- **Alternatives:** games import `../../kit/` (a game no longer works served on its own: reverses rule 4); keep hand-made
  copies and compare them in a test (nothing says which copy is right); the list in `game.json` (that file is launcher
  metadata and is copied into `games.json`); every game gets every module (dead code in each game, and Garden Day's
  service worker would precache files it never loads).
- **Trade-off:** a kit change touches several folders in one commit, and the generated files show up in diffs.

### D-10 — The written conventions are tested; game docs share one shape (2026-11-15)
- **Chosen:** S-2 and S-14 of `docs/STREAMLINING.md`. `tools/check-conventions.mjs` (pure helpers) and
  `tests/conventions.test.js` check, for every listed game: relative URLs only; no import that leaves the game folder, no
  packages, `node:` builtins only in `tests/` and `tools/`; a standard `package.json`; and DOM-free logic modules. The
  launcher's `src/` gets the purity check too. T-3.
- **`"browserModules"` in each game's `package.json`** names the files under `src/` that may touch the browser. Everything
  else in `src/`, including generated `src/kit/` copies, must use no browser global. A listed file that uses none is an
  error, so the list cannot rot. It replaces the module lists the three `CLAUDE.md` files kept in prose (Garden Day's
  was out of date).
- **A game now needs a `package.json`** with `"test": "node --test tests/*.test.js"` (it was optional). Garden Day's script
  was `node --test`; same 175 tests either way.
- **How the purity check reads code:** comments, string contents and regex literals are blanked first; property accesses
  (`x.location`) and object keys (`{ fetch: 'hämta' }`: Garden Day has that translation key) do not count. Names that also
  exist in Node (`URLSearchParams`, `setTimeout`) are not on the list. A `typeof location` guard still counts as browser
  use, which is why Poo Sandwich's `flags.js` is listed; S-10 can make it pure.
- **Docs (S-14):** the three game `CLAUDE.md` files follow one skeleton (Non-negotiable 1..8 / Layout / Commands / Deploy)
  and now state the kit rule and the game's localStorage keys; the three `REQUIREMENTS.md` files use the root status
  legend; READMEs give the same run and test instructions. No rule was removed.
- **Not done:** a common heading format for new decisions in Gem Miner and Poo Sandwich. Their logs are append-only, so
  each file would end up with two formats, which is worse than two files that differ. IDs keep each game's style.
- **Alternatives:** a purity test inside each game, like Gem Miner's (three copies of the checker, the kind of duplication
  this work removes; that test stays for when the game is served on its own); deriving the browser modules from file
  names (no naming rule exists, and renaming files across three games is a larger change than a list); a linter (a
  dependency).
- **Who did what:** Fable wrote the briefs, reviewed both diffs and fixed the object-key false positive; Sonnet
  subagents implemented S-2 and S-14.

### D-11 — kit/storage.js: one storage wrapper, retrying per key (2026-11-15)
- **Chosen:** S-6 of `docs/STREAMLINING.md`. `createStorage(backend, prefix)` with `get`, `set`, `remove`, `text` and
  `persistent`. It merges the two wrappers that Garden Day and Gem Miner had grown from the same start:
  - From Gem Miner (its D24): a refused write is not final. Every write tries the backend again, because a quota error is
    often temporary and giving up for the session leaves an ever older value on disk.
  - From Garden Day (its D-22): this session's value wins for a key whose write was refused, a refused removal never brings
    the old value back, and keys this session has not failed on are still read from the backend.
- **New, beyond both:** failure is tracked per key instead of per session (Garden Day) or not at all (Gem Miner).
  - A key that is safely on the backend is always read from the backend, so a change made in another tab is seen. Gem
    Miner's wrapper answered from memory for any key it had written.
  - A write that succeeds also delivers the keys refused earlier, newest value each. Without that, a refused save would
    stay off the disk until the game happened to write that same key again.
  - `persistent` means "everything written this session is on the backend". Gem Miner's meant "the last write worked",
    which could be true while an earlier save was still only in memory.
- **`prefix` is a required argument** (it was a constant inside each copy); a missing one throws, as a programming error.
- **`text(key)`** returns the raw stored string. Poo Sandwich and the launcher saved the language as a bare `sv`, which is
  not JSON; with the prefixes `poo-sandwich-` and `launcher.` their existing keys keep their names, and `text()` reads the
  old values. So S-7 needs no key migration, only this read.
- **Alternatives:** Gem Miner's wrapper as it was (loses the multi-tab read and overstates `persistent`); Garden Day's as
  it was (one quota error ends saving for the session); returning the raw string from `get()` when it is not JSON (every
  caller that expects an object would have to guard against a string); a `migrate()` helper (nothing needs renaming).
- **Trade-off:** memory holds a copy of every value written this session (Gem Miner's wrapper already did).
- **Not yet used by any part:** adoption is S-7. Garden Day's 9 storage tests were ported and pass unchanged in meaning.

### D-12 — kit/lang.js and kit/langdom.js: one current language per part, t(key, vars) (2026-11-15)
- **Chosen:** S-3. `createI18n(STRINGS)` returns `{ LANGS, DEFAULT_LANG, normalizeLang, pickLang, getLang, setLang, t }`.
  The languages are the table's keys and the first is the default. `t(key, vars, lang = current)` is Garden Day's
  signature: with one current language, pure modules build text without a language being passed to them, which removes
  the three ways the other parts thread it today (`state.lang`, `renderer.setLang`, a `T` wrapper).
- **A factory, not a module-level table:** the kit module holds no texts. Each part keeps `src/i18n.js` with its own
  `STRINGS` and name lookups, and re-exports what `createI18n` returns, so its other modules keep importing `./i18n.js`.
- **`setupLang(i18n, { storage, key, onChange })`** is the browser half: it applies the language rule of D-7 and
  `ADDING-A-GAME.md`, remembers a `?lang=` (the launcher did not; it will from S-4), and returns `apply(root)`,
  `set(lang)` and `bindSwitch(element)`. The page, URL and browser languages can be passed in, which is how the tests run
  it in Node.
- **`data-i18n-title`** is supported alongside the three attributes the launcher and Poo Sandwich use (Gem Miner had it).
- **`stringProblems()` and `missingHtmlKeys()`** live in `kit/lang.js` so the four parts can run the same checks in their
  own i18n tests (S-15) instead of four hand-written versions.
- **Kept out:** number and date formatting (`num`, `dateLocale`), text for data tables (`tx`, `NAMES`) and the Swedish
  wording stay in each part; they depend on the game's data.
- **Alternatives:** `t(lang, key, vars)` everywhere (keeps language threading in three parts and changes Garden Day, the
  largest); a module-level `setStrings()` (hidden coupling, and two tables in one page would collide); translating
  inside the DOM walker only (canvas games draw most text themselves).
- **Verified:** for every key in both languages, the kit's `t()` returns the same text as each part's current `t()`
  (540 lookups, no difference); the four tables and pages pass the kit's checks; switch, `?lang=`, saving and all four
  attributes were exercised in headless Chrome.
