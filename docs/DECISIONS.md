# Decisions & Assumptions Log (Side Quest Project)

> Append-only. Each entry: ID, date, decision, alternatives considered, rationale.
> If a decision is reversed, add a new entry that supersedes the old one (don't delete).
> Game-specific decisions live in `games/<slug>/docs/DECISIONS.md`.

## Decisions

### D-1 — One monorepo in MarEdv/side-quest; games under games/<slug>/ (2026-11-10)
- **Chosen:** Reuse the existing `MarEdv/side-quest` repo. Its history is kept as-is (no rewrite, no force push): one
  commit moves every file into `games/side-quest/`. `MarEdv/poo-sandwich` was rewritten with
  `git filter-repo --to-subdirectory-filter games/poo-sandwich` and merged with `--allow-unrelated-histories`. The
  launcher lives at the root. The unmerged `worktree-statusline-mod` branch was not migrated (it stays in the old clone).
- **Alternatives:** a new `side-quest-project` repo (new URL, both old repos to archive); rewriting both histories into
  subfolders (force push to side-quest); `git subtree add` (keeps commits but old paths, so `git log` on a file needs
  more care); games at the repo root instead of `games/`.
- **Rationale:** Owner chose to reuse the repo and the `games/<slug>/` layout. A move commit keeps existing SHAs and
  links valid, and `git log --follow` still traces files through it.
- **Consequence:** https://maredv.github.io/side-quest/ is now the launcher; Side Quest is at `…/side-quest/games/side-quest/`,
  Poo Sandwich at `…/side-quest/games/poo-sandwich/`.

### D-2 — Retire Side Quest's root service worker with a root sw.js (2026-11-10)
- **Context:** Installed copies of Side Quest have a worker registered at `/side-quest/sw.js` with scope `/side-quest/`, which
  now covers the launcher and every game. Deleting `sw.js` doesn't remove it (a 404 update keeps the old worker; see the
  game's D-26).
- **Chosen:** A root `sw.js` based on the game's `tools/sw-kill.js`. Browsers fetch it on their next visit; it deletes cache
  entries outside `games/` from `sidequest-*` caches and unregisters itself. Nothing registers it. The relocated game keeps
  its own worker (scope `games/side-quest/`) and its cache name, so its tests and code are unchanged.
- **Alternatives:** plain `sw-kill.js` (would also wipe the relocated game's precache, which uses the same cache name);
  renaming the game's cache (changes game code and its tests for no gain).
- **Keep it deployed** for as long as old installs may come back. localStorage (scores, settings) is per origin, so it survives.

### D-3 — Committed games.json, generated by a script (2026-11-10)
- **Chosen:** `tools/build-registry.mjs` writes `games.json` from `games/*/game.json`; the file is committed, and a test
  fails if it is stale.
- **Alternatives:** generate it in CI only (then `npm start` locally would need a build step); list folders at runtime
  (GitHub Pages has no directory listing); hand-edited list in the launcher (easy to forget, no validation).
- **Rationale:** Keeps the no-build-step rule and still makes "add a game" a folder + metadata change.

### D-4 — Launcher links to games; no iframe (2026-11-10)
- **Chosen:** Cards navigate to `games/<slug>/`.
- **Alternatives:** embedding games in an iframe with a shared shell.
- **Rationale:** Games are full-screen canvas games with touch input, safe-area handling and (Side Quest) an installable PWA;
  an iframe would interfere with all of that, and games stay runnable on their own.

### D-5 — Side Quest renamed to Garden Day; folder games/garden-day/ (2026-11-10)
- **Chosen:** Owner renamed the game. The folder (and URL) moved to `games/garden-day/`; the player-facing name changed in the
  title, menu heading, web app manifest, install texts, launcher card and docs. Kept: the gameplay term "side quests",
  localStorage keys (`sidequest.v1.*`) and cache names (`sidequest-*`), so scores, levels and settings survive.
- **Old URL:** `games/side-quest/` became a redirect stub (`game.json` `{ "movedTo": "garden-day" }`, skipped by the
  registry; `index.html` redirects with the query kept) plus a retire `sw.js` that drops cache entries under that folder and
  unregisters itself, for anyone who installed the game there.
- **Root `sw.js` amended:** it no longer deletes a cache it emptied, because the game's worker shares the cache name and could
  be filling it at the same moment.
- **Alternatives:** rename the display name only (stable URL, but a folder name that no longer matches the game); also rename
  storage keys (would wipe players' progress).
- **Trade-off:** an install from the old `games/side-quest/` address keeps opening the redirect; players who want a
  home-screen icon reinstall from `games/garden-day/`. The game was only at that path for a few hours.
