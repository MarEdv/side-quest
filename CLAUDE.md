# Side Quest Project — rules for agents working in this repo

A monorepo of small "side-quest" browser games plus a launcher page, published on GitHub Pages at
https://maredv.github.io/side-quest/ (repo `MarEdv/side-quest`).

## Non-negotiable
1. **Inside `games/<slug>/`, that game's own `CLAUDE.md` and `docs/` apply.** Work on a game follows its rules (its
   requirements, decision log and flags files); paths in those docs are relative to the game folder.
2. **Launcher and repo-level changes** (root `index.html`, `src/`, `tools/`, CI, layout) update `docs/REQUIREMENTS.md`
   in the same commit and log decisions in `docs/DECISIONS.md` (append-only, dated, with alternatives + rationale).
3. **Zero dependencies** (runtime and dev). Vanilla JS ES modules, no build step. Every page works from `npm start`.
4. **Games stay self-contained**: relative URLs only, so a game works both at `games/<slug>/` and served on its own.
   No game may import from the launcher or from another game.
5. **Commit often**, small focused commits. Run `npm test` at the root before committing.
6. Don't ask the owner questions — make a reasonable assumption and log it.

## Layout
- `index.html`, `launcher.css`, `src/launcher.js` – launcher (browser glue). `src/registry.js` – pure registry logic (no DOM).
- `games/<slug>/` – one game per folder: `index.html` + `game.json` (metadata) + the game's own code, tests and docs.
- `games.json` – generated by `npm run registry`, committed. `tests/registry.test.js` fails when it is stale.
- `sw.js` – retires Side Quest's (now Garden Day's) pre-move root service worker (D-2). Never register it; never delete it.
- `games/side-quest/` – redirect stub for Garden Day's old URL (`"movedTo"` in its `game.json`, D-5), with its own retire
  `sw.js`. Not a game; keep it.
- `tools/build-registry.mjs`, `tools/test-all.mjs`; `docs/` – launcher requirements, decisions, `ADDING-A-GAME.md`.

## Commands
- `npm start` → serves on http://localhost:8000 (python3 http.server)
- `npm test` → root tests, then `npm test` inside every game
- `npm run registry` → rebuild `games.json` after adding a game or editing a `game.json`

## Deploy
Push to `main` → GitHub Actions (`.github/workflows/pages.yml`: test, then deploy the repo root) → GitHub Pages.
